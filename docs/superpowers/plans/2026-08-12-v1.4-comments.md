# v1.4 评论系统(Giscus)实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为文章页新增可选的 Giscus 评论系统:默认关闭(env 空值 = 不渲染,保模板开箱 Lighthouse 4×100),用户填好 `.env` 后自动出现在每篇文章正文末尾。

**Architecture:** 新增一个自包含的 `Comments.astro` 组件(框架层),挂在 `ArticlePage.astro` 正文+tags 之后、`InContentAd` 之前。组件读 `import.meta.env.PUBLIC_GISCUS_*`,4 个业务字段任一为空 → 整个组件 `return null`(与现有 `InContentAd.astro` 完全同模式)。启用时注入 Giscus 官方 `<script async data-loading="lazy">`(透传 lazy 给 iframe),并用两个 `MutationObserver` + `postMessage` 让评论区跟随站点暗色模式。mapping = pathname,所以不同 locale 的同一篇文章天然形成独立评论区。

**Tech Stack:** Astro 5.18(static)+ Tailwind CSS 3 + 纯 `.astro` 组件 + vanilla JS(暗色同步,无 JS 框架)。本次不新增组件测试(spec §6 验证靠人工 + Lighthouse,评论涉及外部 GitHub OAuth,自动化测试 ROI 低)。

- [ ] **Step 1: 创建 Comments.astro 组件**

创建 `src/components/article/Comments.astro`,完整内容:

```astro
---
/**
 * Comments — Giscus comment widget for article pages.
 *
 * Gated by env vars — empty config = nothing rendered (same pattern as
 * InContentAd.astro). This preserves the template's out-of-box Lighthouse
 * 4×100: forks without comment config ship zero extra JS.
 *
 * When enabled (all 4 required PUBLIC_GISCUS_* fields filled), injects
 * Giscus's official <script async data-loading="lazy">. The lazy attr
 * is forwarded by client.js to the iframe it creates, so the widget
 * defers until near-viewport — Lighthouse-friendly.
 *
 * Dark mode sync: two MutationObservers + postMessage. Observer A
 * watches <html>.dark class (toggled by ThemeToggle.astro). Observer B
 * watches the .giscus container's childList (catches the async-inserted
 * iframe so we can sync theme once it exists).
 *
 * See docs/superpowers/specs/2026-08-12-v1.4-comments-design.md
 */
import { type Locale } from '~/i18n/routing';
import { getUi } from '~/i18n/ui';

interface Props {
  /** Page locale — drives Giscus UI language (en/ja). */
  locale: Locale;
}

const { locale } = Astro.props;

// Read Giscus config from env ( PUBLIC_ prefix exposes to client via import.meta.env).
const env = import.meta.env as Record<string, string | undefined>;
const repo = env.PUBLIC_GISCUS_REPO;
const repoId = env.PUBLIC_GISCUS_REPO_ID;
const category = env.PUBLIC_GISCUS_CATEGORY;
const categoryId = env.PUBLIC_GISCUS_CATEGORY_ID;
const mapping = env.PUBLIC_GISCUS_MAPPING || 'pathname';

// 4 required business fields — any one empty = disabled (no half-rendered iframe).
const enabled = Boolean(repo && repoId && category && categoryId);

// Giscus data-lang uses short codes matching our locale values.
// Whitelist is defensive (Giscus codes ≠ BCP-47 in edge cases).
const GISCUS_LANG: Record<string, string> = { en: 'en', ja: 'ja' };
const lang = GISCUS_LANG[locale] ?? 'en';

const ui = getUi(locale);
const shared = ui.shared as Record<string, string>;
const heading = shared.commentsHeading ?? 'Comments';
---
{enabled && (
  <section class="mt-12 border-t border-border pt-8">
    <h2 class="text-xl font-bold">{heading}</h2>
    <div class="giscus mt-4" />

    {/* Giscus widget — client.js forwards data-loading=lazy to the iframe */}
    <script
      src="https://giscus.app/client.js"
      data-repo={repo}
      data-repo-id={repoId}
      data-category={category}
      data-category-id={categoryId}
      data-mapping={mapping}
      data-strict="0"
      data-reactions-enabled="1"
      data-emit-metadata="0"
      data-input-position="bottom"
      data-theme="light"
      data-lang={lang}
      data-loading="lazy"
      crossorigin="anonymous"
      async
    />

    {/* Dark mode sync — vanilla JS, is:inline so Astro doesn't bundle/delay it */}
    <script is:inline set:html={`(() => {
  function syncTheme() {
    var theme = document.documentElement.classList.contains('dark') ? 'dark_dimmed' : 'light';
    var iframe = document.querySelector('iframe.giscus-frame');
    if (iframe && iframe.contentWindow) {
      iframe.contentWindow.postMessage(
        { giscus: { setConfig: { theme: theme } } },
        'https://giscus.app'
      );
    }
  }

  // Observer A: watch <html>.dark class (user clicks theme toggle)
  new MutationObserver(syncTheme).observe(document.documentElement, {
    attributes: true,
    attributeFilter: ['class'],
  });

  // Observer B: watch .giscus container childList (client.js async-inserts iframe)
  // + initial sync attempt in case iframe already exists at DOMContentLoaded.
  document.addEventListener('DOMContentLoaded', function () {
    var container = document.querySelector('.giscus');
    if (container) {
      new MutationObserver(syncTheme).observe(container, { childList: true, subtree: true });
    }
    syncTheme();
  });
})();`} />
  </section>
)}
```

**关键实现说明(实现者必读)**:

1. **`enabled` 判定**:4 个业务字段(repo/repoId/category/categoryId)用 `Boolean(a && b && c && d)`。`mapping` 有默认值 `pathname`,不参与判定。这与 `InContentAd.astro` 的 `{adKey && (...)}` 模式一致。

2. **`set:html` 而非 `<script>` body**:Astro 的 `<script>` 标签默认会被打包(bundled)和提升(hoisted),这会破坏 `is:inline` 的语义。用 `set:html={...}` 把整段 JS 作为字符串内联进 `<script is:inline>`,确保它原样输出到 HTML、不被 Astro 处理。这是 Astro 内联脚本的官方推荐写法(参见 SearchButton.astro / ThemeToggle.astro 的 `<script is:inline>` 用法)。

3. **`var` 而非 `const/let`**:内联脚本用 `var` 是为了最大化浏览器兼容性(虽然现代浏览器都支持 const/let,但 is:inline 脚本不走 Astro 的 transpile,保持保守)。

4. **observer B 的 `subtree: true`**:`.giscus` 容器里 client.js 可能插入多层嵌套元素后才出现 iframe,`subtree: true` 确保捕获到。`syncTheme()` 内部的 querySelector + if 守卫确保不存在 iframe 时不报错。

5. **不用 `@load` 绑定 iframe**:iframe 是 client.js 运行时动态创建的,HTML 里写 `<iframe @load>` 抓不到它。observer B 就是用来替代 `@load` 的。

# 评论系统（Giscus）

AnvilWiki 内置可选的评论系统，基于 [Giscus](https://giscus.app) —— 评论通过 GitHub 登录后存到你的仓库的 **GitHub Discussions** 里。零服务器、零数据库，构建时静态，评论运行时按需加载。

**默认关闭。** 不配置时文章页不显示评论区，模板保持 Lighthouse 4×100。填好 5 个环境变量后自动启用。

---

## 前置条件

1. 一个 **public** GitHub 仓库（可以是你的 wiki 源码仓库本身，也可以是专门建一个评论仓库）
2. 该仓库开启 Discussions：Settings → General → Features → 勾选 Discussions
3. 安装 [giscus app](https://github.com/apps/giscus) 到该仓库

## 配置步骤

1. 打开 https://giscus.app
2. 在「Configuration」区填你的仓库名（如 `yourname/your-wiki`）
3. 页面会自动生成一串配置，记下这 5 个值：
   - `data-repo` → `PUBLIC_GISCUS_REPO`
   - `data-repo-id` → `PUBLIC_GISCUS_REPO_ID`
   - `data-category` → `PUBLIC_GISCUS_CATEGORY`
   - `data-category-id` → `PUBLIC_GISCUS_CATEGORY_ID`
   - `mapping` → `PUBLIC_GISCUS_MAPPING`（默认 `pathname`，通常不用改）
4. 把这 5 个值填到 `.env`（参考 `.env.example`）
5. `pnpm dev`，访问任意文章页，评论区出现在正文下方

## 验证

访问 `http://localhost:4321/bosses/gelum`（或你的任一文章页）。正文 + 标签下方应出现评论区。点「Sign in with GitHub」登录后可发表评论。

## 多语言行为

不同 locale 的同一篇文章是**独立的**评论区：

| URL | 评论区 |
|---|---|
| `/bosses/gelum`（英文） | Discussion A |
| `/ja/bosses/gelum`（日文） | Discussion B（与 A 互不影响） |

这是 `mapping=pathname` 的自然结果，符合「日文用户用日文讨论、英文用户用英文讨论」的预期。Giscus 的界面语言（按钮、提示）会自动跟随页面 locale（en/ja）。

## 暗色模式

评论区会**自动跟随**你站点的暗色模式切换，无需任何配置。主题切换器 toggle `.dark` class 时，评论区通过 postMessage 实时同步主题。

## 关闭评论

把 `.env` 里的 5 个 `PUBLIC_GISCUS_*` 字段留空（或删除）即可。`Comments` 组件会 `return null`，文章页不渲染评论区，零 JS 加载。

## 常见问题

**评论不显示？** 逐项检查：
- 仓库是否 public？（private 仓库 Giscus 无法访问）
- Discussions 是否开启？（Settings → General → Features）
- giscus app 是否安装到该仓库？
- 4 个必填字段是否都填了？（任一为空 = 组件不渲染）
- `data-category-id` 是否对？（不是 category 名字，是那串 `DIC_...` 开头的 ID）

**登录后页面卡住？** 确认你没有用 ad-blocker 拦截 `giscus.app` 域名。某些隐私扩展（uBlock Origin、Privacy Badger）会误拦 Giscus 的 OAuth 回调。

**改了文章 URL，评论丢了？** pathname mapping 下，URL 变了会创建新的 Discussion。旧评论仍在你的仓库 Discussions 里，可手动找回。建议文章 URL 一旦发布不要改动。
